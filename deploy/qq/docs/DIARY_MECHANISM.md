# 私人日记机制（0.9.0）

当前实现与完整测试见 [长期记忆与日记优化](MEMORY_DIARY_OPTIMIZATION.md)。日记仍在社交生活插件内；没有安装第二套日记插件。

## 当前流程

1. 每天 21:00 起，聊天空闲 120 秒后领取当天唯一任务；重启保留任务状态，原文件存在则不覆盖。21:00 生成只能涵盖当天截至生成时的消息，不包含当天随后发生的聊天。
2. 只读主人 QQ 私聊、许可群聊和已许可的本地聊天。按小时读取当天消息，移除旧版每时段 25 条的采样上限；保留双方发言。通知、命令、图片／表情描述、明确验收探针和敏感内容仍过滤。超长单条消息保留前 1200 字并标记截断。
3. 同会话内按时间间隔组织场景，`BOT` 表示角色，其他人物使用平台与真实账号区分后的临时标识。只有真实 `reply_to` 建立明确回复关系。编号不作为新的长期身份写回。
4. DeepSeek Flash 使用原生 `memory` 任务，温度 0.2，分批整理事件、重要程度及氛围。共享说话人映射和明确消息列名减少重复元数据；原始结构仍完整保存。所有事件引用必须属于本批已有场景，模型不能改写说话人。数量受限，异常明确失败，不用截断 JSON 或猜测 ID 兜底。
5. 全部合格素材都会进入整理批次，但成文只挑最多两个主题，通常围绕一个细节展开。按选中素材最多两次只读检索既有长期记忆，过去背景不会被当作今天的新事件。
6. 本地 Qwen3-8B 自行决定篇幅，没有固定字数或最低长度；最多一句事实背景，其余是自己的观察、联想、疑问。允许少量有来源的短引用，避免复述多轮对话。虚拟日程明确标为设定，不得成为真实线下经历。
7. 正文做长度、敏感信息和推理文本检查。此检查不是语义真实性证明；自动审阅只是测试工具，不是每天额外执行的生产环节。
8. 新流程不通过任何 QQ 日记投递路径发送正文，也不进入空间、长期记忆或画像。调用耗时、Token 和阶段错误分别保存；失败不自动重试。

## 配置与关闭

实际配置为 `plugins/social_life_plugin/config.toml` 的 `[diary]`：

- `daily_events_enabled=true`：启用两阶段新流程；改为 false 可以单独关闭，回到旧采样／选材路径。
- `event_task="memory"`、`event_model_name="deepseek-flash"`、`event_batch_chars=9000`、`event_max_batches=24`。
- `daily_message_limit=5000`：可用消息安全上限；超过上限或分批预算时明确报错，不悄悄只处理最后一段。
- `source_max_chars=4000`：最终事件写作材料预算，与全天读取数量不是一回事。
- `model_name="qwen3-8b-local"`、`max_tokens=1536`：这是请求输出上限，不是目标长度；正文仍保留1500字符的异常长文检查。
- `include_long_term_memory=true`、`memory_limit=4`、`memory_max_chars=1200`。
- `private_delivery_authorized=false`、`auto_private_delivery=false`；新流程还在投递函数中强制拒绝日记发送。

旧路径保留了原先更严格的引号／复述检查；新流程不使用一律拒绝引号的旧门槛。完整回退应恢复备份配置和源码，而不只是切换一个开关。

## 文件与管理

都在 `data/MaiMBot-plugin-data/jycao.social-life/` 内，目录 700、文件 600：

- `diaries/YYYY-MM-DD.md`：正式日记，自动任务不会覆盖。
- `diary-previews-<revision>/YYYY-MM-DD.md`：独立预览，相同日期／revision 不重复领取。
- `diary-events/<run>/YYYY-MM-DD.json`：私人场景、事件整理、模型原始结果、写作输入／草稿、阶段指标与错误。可能含私人内容，禁止提交 Git。
- `diary-versions/<revision>/YYYY-MM-DD.md`：管理员编辑或归档前的旧版本。

受 WebUI 管理员认证保护的查询／动作和本机 CLI 均可用。日期预览与修改示例见优化报告。归档只移走当前文件，旧版本保留；没有执行任何现有日记的编辑、归档或永久删除。
