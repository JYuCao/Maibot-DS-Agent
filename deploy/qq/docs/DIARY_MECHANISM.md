# 私人日记取材与写作（0.8.0）

本次发现的问题属于日记选材和成文：原来均匀抽取单句，会拆散原对话；本地验收消息混入素材，表情标签被当成说话内容，模型又把虚拟活动和真实经历混在一起。没有因此修改聊天数据库、人物画像或已有长期记忆。

## 当前流程

1. 每天 21:00 起，聊天空闲后生成一次；原文件存在时不覆盖。
2. 按用户最新授权，优先主人 QQ 私聊和已许可本地聊天，其次许可群聊。QQ 私聊仅取配置的 `access.administrator`，不会遍历其他人的私聊。
3. 丢弃通知、命令、图片／表情的自动描述和明确的部署验收探针。同一会话内保留连续片段，不再把一天的零散句子均匀拼接。
4. 为人物分配稳定片段标识；`BOT` 才是鲸鲸。只有平台实际 `reply_to` 建立的关联才能作为明确回复关系，相邻发言不自动构成问答。本地、私聊、群聊来源分别标识。
5. 用聊天回复模型选择最多两段材料，只允许返回已有场景 ID，不接受它自行编写的事件或改动说话人。私聊和鲸鲸实际参与的片段优先。
6. 只针对选定材料有界检索历史记忆，历史背景不能变成今天的新事件。结构化素材直接传入写作，不再重复编码为含大量转义引号的字符串。
7. 写作侧强调内心感受、在意的原因和想法变化，聊天经过最多约四分之一。不直接引用台词，不按早午晚列流水账。保留明确的虚拟日程氛围，不能把它变成真实身体或线下经历。
8. 保存前检查明显的直接引语和问答式流水账；不合格时记录具体阶段与错误类型，不保存、不自动重试，不以编造材料兜底。此检查不是完整的语义事实证明。

配置：`plugins/social_life_plugin/config.toml` 中的 `diary.include_qq_private=true`、`include_local_private=true`、`structured_selection_enabled=true`。每天增加一次短的本地选材调用，写作模型由 `diary.model_name` 决定。输出目标仍为约 500–800 字，材料不足时允许短写。

## 保存与预览

- 正式日记：`data/MaiMBot-plugin-data/jycao.social-life/diaries/`。
- 新版预览：同一插件数据目录下 `diary-previews-<revision>/`。不会覆盖正式日记，不投递 QQ 或空间。
- 受保护的 WebUI 插件动作 `social/actions/diary_preview` 可使用不同 `revision` 生成独立预览；同一日期、同一 revision 只领取一次，不自动补发失败任务。
- 原日记与修改前源码／配置备份：`data/deployment-config-backups/diary-grounding-20261025-223151/`。

日记不进入聊天检索、人物画像、长期记忆或空间生成。私聊可用于主人本地日记，不代表日记可以公开。预览同样属于私有文件，不要提交 Git 或粘贴到公开报告。

验证覆盖：双人群聊不被标为 BOT 发言、真实回复 ID 归属、媒体与探针过滤、私聊取材显式开关与优先级、选材 ID 校验、预览不覆盖原文且不发送消息。主人已认可第一份 Qwen 预览以私聊为主、带碎碎念和感受的风格，人物归属仍有改进空间。第二份被当前严格质量检查拒绝；本快照保留实际实现，尚未进一步放宽质量门槛。正式日记未覆盖，成文模型仍为本地 Qwen，未切换 DeepSeek。
