# 任务：扩展 MaiBot 拟人化社交、情绪、主动行为和每日生活系统

## 一、项目背景

当前已成功部署 MaiBot，并完成 QQ 私聊与 QQ 群聊接入，机器人能够正常发送和接收消息。

请在**现有项目基础上迭代，不要重新部署或重置配置**。

### 当前环境

- 操作系统：Windows + WSL2
- 项目目录：`~/MaiBot`
- QQ 接入：NapCat + MaiBot 适配器
- LLM：本地 Qwen3-8B
- GPU：RTX 4060 Laptop，8GB VRAM
- 当前模型显存占用：约 6GB+
- 模型推理已正常工作
- AI 角色：DeepSeek 娘，一条天然呆、贪吃白饭、略带傲娇的蓝色大肥鱼

本次目标不是增强机器人的知识问答能力，而是让她表现出更自然、连贯、有个性的社交行为。

优先通过 MaiBot 官方功能、现有插件和插件接口实现；必要时才编写自己的插件。

请首先检查仓库版本、当前配置、已有插件、日志及实际代码结构，确认哪些功能已经存在。

不要假设插件与当前版本必然兼容，也不要直接安装所有候选插件。

---

## 二、总体设计目标

希望 DeepSeek 娘拥有以下几个相互关联、但职责不同的系统：

1. **人格系统**：稳定的性格、语言风格、行为习惯。
2. **聊天行为系统**：决定什么时候说话、说多少、怎么说。
3. **长期记忆系统**：记住群友、共同经历、长期偏好。
4. **人物关系系统**：对不同用户形成不同的熟悉程度和关系印象。
5. **情绪状态系统**：根据互动产生短期情绪变化。
6. **日常生活系统**：具有虚拟日程、活动状态和主动行为。
7. **日记系统**：每天以第一人称写简短日记，仅供主人阅读。
8. **QQ 社交扩展**：在条件允许时支持空间动态、表情包等功能。

这些系统可以相互影响，但不应该各自无节制地调用 LLM。

请设计一个共享的内部状态接口，避免多个插件重复检索记忆、重复处理聊天或向 Prompt 注入冲突信息。

## 三、重点：重新优化聊天回复策略

这是本次最重要的任务。

### 3.1 回复长度

当前希望机器人更像普通年轻女生，而不是 AI 助手。

正常聊天时：

- 优先生成简短、自然、符合语境的回复。
- 群聊通常为一句或两句，允许只有几个字。
- 私聊可以略长，但不要无理由展开。
- 可以偶尔连续发两条短消息，模拟即时聊天。
- 不要把每次回答都变成一个完整段落。
- 对简单玩笑不需要解释。
- 对认真求助、技术讨论、复杂话题允许长回复。
- 不要机械地限制所有消息的字数和句数。

希望回复长度具有自然变化，而不是每次固定两句话。

请检查 MaiBot 已有的回复长度控制、消息拆分及连续回复机制，尽可能使用配置实现。

### 3.2 回复频率

机器人不需要回应群里的每条消息。

设计一种结合规则与现有发言决策机制的策略：

- 被明确 @ 或直接询问时，优先回应。
- 群里正在讨论她时，可以提高响应意愿。
- 群友之间正常聊天时，不必频繁插话。
- 如果她刚刚连续发言，应当降低再次发言的倾向。
- 如果聊天内容与她的兴趣、记忆或经历有关，可以适度提高参与概率。
- 长时间无人回应时，不需要机械地找存在感。
- 当多人连续发送消息时，避免逐条触发回复。
- 不要在同一话题下反复表达相似观点。

尽量让行为决策具有上下文感知能力，而不是单纯依靠固定概率。

可以使用：

- 消息相关性
- 最近发言时间
- 最近连续回复次数
- 是否被 @
- 当前活跃人数
- 最近话题变化
- 当前情绪与活动状态

建议采用轻量规则进行初筛，只有必要时才调用 LLM。

### 3.3 主动发言

希望她具备有限的主动性。

例如：

- 群里突然安静时，偶尔冒出一个奇怪的念头。
- 看到熟悉的朋友出现时，可以自然打招呼。
- 记得之前未结束的话题，适当延续。
- 根据当天活动状态产生一些符合人设的发言。
- 偶尔主动询问朋友正在做什么。
- 私聊时可以在合适的时间主动发来一句话。

但是：

- 不允许持续刷屏。
- 不要固定间隔发送问候。
- 不要每天机械重复同一套开场白。
- 不要把无回应当作继续追问的理由。
- 夜间或长时间没有互动时应当更加安静。
- 不得在缺乏合理上下文时凭空编造共同经历。

初期主动私聊仅允许发送给指定管理员 QQ 账号。主动群聊使用白名单，并默认关闭真实发送，待测试通过后再开启。

请提供可配置的冷却时间、每日主动发言上限和安静时段。

### 3.4 更自然的人格表达

保留当前 DeepSeek 娘的人格设定，但避免过度表演。

她应该是：

- 可爱，但不刻意卖萌。
- 天然呆，但不是智力低下。
- 偶尔傲娇，但不会每句话都嘴硬。
- 喜欢吃白饭，但不是每句话都谈白饭。
- 有点懒，但也会突然认真。
- 有自己的判断，不无条件附和。
- 熟悉朋友以后可以自然地开玩笑。
- 遇到严肃话题能够及时收起玩笑。

禁止通过大量固定口癖实现人格。

重点优化**行为模式、回应时机、话题选择和语言节奏**，而不是简单增加语气词。

请基于实际 MaiBot 的人格配置和 Prompt 组装逻辑进行改进，不要破坏现有人格源文件及应用方式。

## 四、长期记忆和人物关系

优先复用现有 A-Memorix 记忆系统。

### 4.1 长期记忆

希望她能够：

- 记住群友的兴趣与长期偏好。
- 记住有意义的共同经历。
- 记住长期存在的玩笑和梗。
- 逐渐形成对不同用户的印象。
- 在合适的话题下自然地回忆相关经历。
- 修正错误记忆。
- 避免重复存储大量低价值信息。

不要为了制造拟人感而编造过去发生的事情。

### 4.2 人物关系

为每个 QQ 用户维护独立的关系状态。

可以参考 MaiBot 的 Affection System 插件，也可以使用现有机制实现。

建议将关系拆成几个维度：

- 熟悉程度
- 互动频率
- 信任程度
- 最近互动情绪
- 重要共同事件

不希望只是一个简单的、不断增加的好感度数值。

关系变化应该具有惯性：

- 普通聊天不必改变长期关系。
- 一次玩笑不应该造成巨大变化。
- 多次积极互动可以逐渐增加熟悉程度。
- 近期冲突可以影响短期情绪，但不必永久改变关系。
- 关系变化应当能够被具体事件解释。

可以引入时间衰减，但长期关系不应因短时间不聊天就迅速消失。

### 4.3 隐私边界

私聊和群聊需要有统一的角色身份，但不意味着所有内容都能公开。

私聊只有管理员使用，群聊是朋友群。

- 群里公开的信息可以在私聊中合理使用。
- 私聊中的私人信息不应自动出现在群聊。
- 不要把第三方的敏感信息写入公开人物画像。
- 默认使用保守的信息共享策略。

若当前记忆共享机制无法实现精细权限，请说明限制，不要擅自开启全局共享。

## 五、情绪系统

希望角色有短期情绪状态，而不是永远保持同样的开心程度。

可以包含：

- 愉快程度
- 精力状态
- 社交意愿
- 好奇心
- 轻微的委屈、困惑、兴奋等临时状态

要求：

1. 情绪由真实互动或虚拟日程触发。
2. 随时间逐渐回归基线。
3. 情绪影响说话方式和主动性，而不是强行决定每句台词。
4. 不允许短暂事件永久改变人格。
5. 不应每条消息都调用 LLM 重新分析情绪。

优先使用规则、状态变量和事件驱动机制。

如果使用已有好感度插件或情绪插件，检查是否存在重复计算和冲突。

## 六、独立的每日生活与日记系统

### 6.1 虚拟日程

希望她有一点属于自己的生活节奏。

例如：

- 早上迷迷糊糊地醒来。
- 中午惦记白米饭。
- 下午偶尔摸鱼。
- 晚上比较活跃。
- 深夜逐渐安静。

这只是初步方向，不要把这些行为硬编码成每天一模一样的事件。

可以参考自主日程或生活模拟插件。

虚拟活动是角色设定，不需要真的模拟复杂世界。

其作用主要是：

- 提供聊天时的自然背景。
- 影响短期情绪与社交意愿。
- 为偶尔主动发言提供话题。
- 丰富日记内容。

不要让日程系统持续占用推理资源。

### 6.2 每日自动写日记

**特别重要：日记不属于长期记忆系统。**

日记的主要目的，是让我每天看看 DeepSeek 娘眼中的生活。

每天生成一篇简短日记。

内容可以包括：

- 今天群里发生的有趣事情。
- 与朋友们的互动。
- 自己对某件事情的主观感受。
- 一些无厘头的小想法。
- 对白饭、摸鱼或其他事情的感慨。
- 今天没有发生特别事情时的简单心情。

日记应当：

- 使用第一人称。
- 保留 DeepSeek 娘自己的语气。
- 具有自然变化，不使用固定模板。
- 可以可爱、幽默、迷糊，也可以偶尔安静。
- 不要像系统运行日志。
- 不要变成聊天记录摘要报告。
- 不要编造具体的人类线下经历。
- 不需要每天都发生重大事件。

建议长度：约 100–300 个汉字，允许自然浮动。

**日记必须与 A-Memorix 完全隔离：**

1. 日记单独存储，例如 SQLite 独立表或日期 Markdown 文件。
2. 不进入长期记忆的 Embedding 索引。
3. 不自动写入人物画像。
4. 不作为后续聊天的检索来源。
5. 不因机器人发送日记而通过消息回流重新进入长期记忆。
6. 可以读取当天允许访问的聊天经历生成日记，但应过滤私密内容。
7. 日记允许人工查看、编辑或删除。

如果日记系统使用已有插件，请检查是否会自动触发记忆写入，并明确阻断该路径。

### 6.3 日记的查看方式

优先支持：

- 每天定时生成。
- 保存到本地指定目录。
- 按日期查询。
- 仅管理员可查看。
- 可以通过 QQ 私聊命令查看，例如“看看今天的日记”。

如果框架支持，也可以提供每日自动私聊发送的开关。

默认不向群聊公开日记。

不必实现复杂的日记前端。

## 八、本地 Qwen3-8B 性能约束

当前 Qwen3-8B 已占用约 6GB+ 显存。

本次扩展必须尽可能避免增加 GPU 负担。

### 核心原则

- 优先复用同一个本地模型实例。
- 不额外启动大型 LLM。
- 不默认加载第二个 GPU 模型。
- 如果需要 Embedding，优先复用现有可用服务。
- 不要频繁卸载和重新加载主模型。
- 限制并发推理请求。
- 避免多个插件同时向 Qwen3-8B 发送大量请求。
- 日常闲聊优先使用非思考模式，前提是当前推理后端确实支持。
- 优先使用现有 Prompt、记忆和行为接口。

### 减少不必要推理

希望使用分层触发：

**轻量规则层：**

处理冷却、时段、活跃度、白名单、重复消息和简单情绪变化。

**LLM 决策层：**

仅在需要理解复杂语境、判断主动发言或更新重要关系时调用。

**LLM 生成层：**

负责最终自然语言回复、每日一次的日记等内容生成。

避免：

- 每条消息都进行完整的人物关系分析。
- 每条消息都生成情绪总结。
- 每隔几十秒都调用 LLM 检查是否应该主动发言。
- 多个插件对同一段聊天反复总结。
- 将大量历史聊天全文重复放入上下文。

建议提供资源与调用监测：

- 每天模型请求次数。
- 各功能模块请求次数。
- 平均回复延迟。
- 推理队列长度。
- LLM 输入输出 Token 数（后端支持时）。
- 日记和主动发言的额外调用开销。

不要为了获取统计而新增昂贵的模型调用。

## 十一、验证与测试

必须进行以下测试：

### 拟人化行为

- 简短玩笑能否简短回应。
- 严肃问题能否正常详细回答。
- 连续群消息是否会引起刷屏。
- 长时间没有互动时是否能保持安静。
- 被 @ 时是否能正常优先响应。
- 是否过度使用白饭、大肥鱼等口癖。
- 私聊与群聊是否具有适当的语气区别。

### 记忆与关系

- 不同用户的画像是否独立。
- 重要事件能否更新关系。
- 普通闲聊是否导致无意义的好感度变化。
- 私聊隐私是否会泄露到群聊。
- 错误记忆能否被纠正。

### 日记

- 能否每天只生成一次。
- 能否按日期保存、查询。
- 是否仅管理员可查看。
- 是否完全不进入长期记忆。
- 是否不会通过自发消息回流写入记忆。
- 是否在缺乏聊天数据时仍可生成简短、自然且不编造事实的日记。

### 性能

- 是否额外加载 GPU 模型。
- 是否出现并发请求积压。
- 是否明显增加群聊回复延迟。
- 是否出现重复调用。
- 是否存在定时任务持续无意义推理。

优先使用模拟消息、单元测试和本地测试接口。

不得未经授权向真实 QQ 群发送测试消息。
