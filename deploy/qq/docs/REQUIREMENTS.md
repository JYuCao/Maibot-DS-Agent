# 任务：部署并配置具有长期记忆的拟人化 QQ AI 角色

## 1. 项目背景

我希望部署一个能够在 QQ 私聊和 QQ 群聊中长期存在的拟人化 AI 角色。

当前环境：

- 操作系统：Windows + WSL2 Ubuntu
- 当前工作目录：`~/MaiBot`
- LLM：DeepSeek API，暂不使用本地大模型
- 项目：MaiBot（https://github.com/Mai-with-u/MaiBot）
- QQ 接入：NapCat + 官方推荐的 MaiBot 适配器
- 部署位置：宿舍笔记本电脑，初期本地运行
- 硬件：RTX 4060 Laptop，但不希望占用 GPU
- 后续可能迁移到 Linux 服务器

请首先检查当前目录中的项目文件、Git 状态、README、部署文档和配置文件，识别当前 MaiBot 的实际版本。

**所有操作必须基于仓库中的真实代码与当前版本文档，不要凭空假设配置字段、接口或文件路径。**

## 2. 最终功能需求

### 2.1 QQ 接入

实现以下功能：

1. 使用普通 QQ 小号登录 NapCat。
2. 支持指定用户的 QQ 私聊。
3. 支持指定 QQ 群聊。
4. 私聊和群聊使用同一个 AI 角色。
5. 支持 QQ 用户身份识别和群成员身份识别。
6. 支持消息上下文管理。
7. 通过白名单限制允许交互的用户和群。

登录、扫码、填写 API Key 等需要本人完成的步骤，可以暂停并告诉我如何操作。

### 2.2 拟人化聊天

这个 AI 不是客服、知识问答助手或传统的 ChatBot。

我希望它更像一个拥有独立人格的朋友。

具体要求：

- 具有稳定的人格、兴趣、语言习惯和说话风格。
- 回复应自然、口语化，避免典型 AI 助手的表达方式。
- 不必对每条消息做出回答。
- 能够根据聊天气氛和上下文判断什么时候发言。
- 可以适当开玩笑、吐槽、接梗。
- 不应该总是长篇大论。
- 可以表达不确定、不同意或暂时不感兴趣。
- 保持人设的一致性，但允许随经历逐渐发展。
- 不需要假装自己是真人，参与者应当知道它是 AI。

请先检查 MaiBot 当前已有的人格系统、发言决策系统和相关配置。

尽可能复用项目原有能力，不要重复实现已有功能。

初始人格可以采用自然、随性、略带冷幽默的年轻朋友风格。将人格配置单独保存，方便后续修改。

### 2.3 长期记忆

这是本项目非常重要的功能。

目标不是简单保留聊天记录，而是使 AI 形成长期、连贯的社交经历。

需要实现或配置：

1. 记住用户的兴趣、偏好、习惯等长期信息。
2. 记住重要的共同经历。
3. 维护不同 QQ 用户的身份与人物画像。
4. 记住群成员之间的关系与互动。
5. 能够根据当前话题检索相关的历史记忆。
6. 避免把所有历史记录直接塞进 Prompt。
7. 支持记忆更新、纠错、合并和遗忘。
8. 支持私聊与群聊之间的身份关联和记忆共享。

优先研究 MaiBot 已有的 A-Memorix 记忆系统，以及相关 Embedding、检索和共享机制。

需要特别注意：

**共享记忆不代表可以随意泄露私聊内容。**

希望区分：

- 角色自己的长期经历
- 用户公开的人物画像
- 私聊专属信息
- 群聊共享经历

可以允许群聊利用合理的公开背景信息，但不应主动暴露私聊中的个人隐私。

如果现有 MaiBot 无法实现细粒度记忆权限，请先使用保守的隔离配置，并说明后续如何实现，不能直接把全部私聊记忆暴露给群聊。

### 2.4 DeepSeek API

使用 DeepSeek 官方 API 作为主要语言模型服务。

请：

1. 检查当前官方支持的模型 ID。
2. 配置 MaiBot 中回复生成、发言决策、记忆处理等所需的模型组件。
3. 为 Embedding 选择合适的 API 或轻量 CPU 方案。
4. 尽量降低不必要的 Token 消耗。
5. 配置上下文长度、回复长度和请求频率。
6. 设置合理的超时、重试和错误处理。
7. 提供 API 消耗统计或监测方法。

API Key 必须通过环境变量、未跟踪的配置文件或项目官方支持的安全方式提供。

不要将密钥硬编码进代码、提交到 Git、打印到日志或写入报告。

### 2.5 群聊行为

群聊中的 AI 应更接近普通群友。

请检查并合理配置：

- 主动发言概率或决策机制
- 被 @ 时的响应行为
- 对话相关性判断
- 连续发言限制
- 防刷屏机制
- 群成员身份与上下文识别
- 表情包、图片等消息类型的支持情况

初期采用保守策略，避免过于频繁地发言以及产生大量 API 费用。

未经我确认，不要自动向真实 QQ 群发送测试消息。

## 3. 部署要求

优先考虑 WSL2 + Docker Compose，并使用当前仓库官方支持的部署方式。

请依次完成：

1. 检查系统环境、Docker、Docker Compose、WSL 网络和目录权限。
2. 检查 MaiBot 仓库状态及当前配置。
3. 确定适配当前版本的 NapCat QQ 接入方案。
4. 准备环境变量和配置文件。
5. 部署 MaiBot、NapCat、适配器以及必要的依赖。
6. 配置 DeepSeek API 和相关模型组件。
7. 配置人格、会话管理和长期记忆。
8. 配置持久化目录、日志和服务重启机制。
9. 检查容器及服务运行状态。
10. 进行不涉及真实 QQ 消息发送的基础测试。

要求：

- 尽量不占用 GPU。
- 不要安装不必要的大型依赖。
- 所有记忆和数据库数据需要持久化。
- 便于以后迁移至其他 Linux 主机。
- 保持官方项目结构，尽量避免侵入式修改。
- 不要覆盖现有配置或删除数据库，除非我明确确认。
- 不要随意执行破坏性命令。
- 不要擅自开放公网管理端口。

## 4. 工作方式

不要只给我一份部署教程，请在当前工作环境中实际执行可以安全自动完成的步骤。

遵循以下原则：

**第一阶段：环境检查**

检查项目、依赖和当前部署状态，输出简要结论。

**第二阶段：部署和配置**

优先使用官方现有功能。缺少必要配置时创建配置模板，缺少依赖时安装必要依赖。

**第三阶段：功能验证**

检查：

- MaiBot 是否成功启动
- NapCat 与适配器是否连通
- DeepSeek API 是否能正常调用
- 人格配置是否生效
- 记忆服务是否可用
- 私聊与群聊的会话隔离及共享规则是否正确
- 日志是否存在明显错误

在未授权真实消息发送时，优先使用模拟消息或离线测试。

**第四阶段：交付**

最后总结：

1. 已完成的工作
2. 修改过的文件
3. 各项功能的测试结果
4. 仍需我手动完成的步骤
5. 项目启动、停止、重启命令
6. 日志查看方法
7. 后续调整人格、记忆和发言频率的方法
8. 迁移到服务器时需要备份的目录

另外，生成一份简洁的 `DEPLOYMENT_NOTES.md`，记录必要的部署信息、配置路径和日常维护命令，不包含任何密钥。

## 5. 优先级

请严格按照以下优先级工作：

P0：MaiBot + NapCat + DeepSeek API 成功运行。

P1：QQ 私聊、群聊均能够正常收发消息，并具备稳定人设。

P2：配置长期记忆、人物画像和安全的跨会话记忆共享。

P3：优化主动发言、拟人化行为、Token 消耗。

P4：为将来扩展记忆系统和迁移服务器做好准备。

不要为了实现高级功能而阻碍基础部署。
